# Свой агрегатор VPN-подписок (VLESS/VMess/Trojan/SS)

Собирает конфиги из твоих источников, дважды реально тестирует каждый
через Xray (не просто пинг, а настоящий запрос в интернет + проверка
скорости закачки) и публикует **две маленькие подписки только с лучшими
конфигами**: обычную и отдельно белые списки.

## Как развернуть (один раз)

1. Создай **публичный** репозиторий на GitHub.
2. Залей в него все файлы из этого проекта, сохранив структуру папок:
   ```
   sources.txt
   sources_whitelist.txt
   manual.txt
   manual_whitelist.txt
   blacklist.txt
   requirements.txt
   scripts/build_subscription.py
   .github/workflows/update.yml
   ```
3. **Settings → Actions → General → Workflow permissions** →
   **"Read and write permissions"** → Save.
4. Источники уже вписаны (см. ниже), можно сразу запускать, либо
   отредактировать под себя.
5. **Actions → Update VPN Subscription → Run workflow** — запусти вручную
   первый раз, посмотри что всё прошло без ошибок (займёт пару минут —
   тестирование в 2 раунда с паузой между ними).
6. Появятся два файла — твои две ссылки:
   ```
   https://raw.githubusercontent.com/<ник>/<репо>/main/output/subscription.txt            (обычная, для Wi-Fi/безлимитного мобильного)
   https://raw.githubusercontent.com/<ник>/<репо>/main/output/subscription_whitelist.txt   (белые списки, для жёстких ограничений)
   ```

## Как теперь фильтруются конфиги (по твоим требованиям)

Раньше публиковалось всё, что прошло один пинг — из-за этого подписка
раздувалась. Теперь два раунда:

1. **Раунд 1 (быстрый отсев)** — проверяется пинг вообще всех собранных
   конфигов. Проходят только те, у кого задержка ≤ `--max-latency-ms`
   (по умолчанию 350 мс).
2. **Пауза** (`--round-gap`, по умолчанию 30 сек) — чтобы не засчитать
   конфиг, который ответил один раз случайно.
3. **Раунд 2 (финал)** — те же конфиги проверяются ещё раз: пинг +
   реальная скорость закачки 512 КБ через прокси. В подписку попадают
   только те, кто **снова** ответил быстро **и** показал скорость
   ≥ `--min-speed-kbps` (по умолчанию 250 КБ/с).
4. Из прошедших берутся **топ-`--max-output`** (по умолчанию 20) —
   отсортированные по скорости, лучшие первые.

Конфиг, который прошёл раунд 1, но не подтвердился в раунде 2 (мигает /
перегружен) — в подписку не попадёт. Именно так отсекаются "неправдоподобные"
пинги.

## Разделение normal / white

- `sources.txt` + `manual.txt` → обычная подписка (`output/subscription.txt`)
- `sources_whitelist.txt` + `manual_whitelist.txt` → подписка белых списков
  (`output/subscription_whitelist.txt`)
- `blacklist.txt` — общий, действует на обе категории сразу.

Оба потока тестируются вместе за один прогон, но публикуются раздельно,
каждый со своим топ-`--max-output`.

## Ручной отбор (если хочешь сам решать)

Смотри `output/report.json` после каждого запуска — там оба раунда по
каждому конфигу (пинг, скорость, ошибка, категория). Понравившийся конфиг
скопируй в `manual.txt` (обычная) или `manual_whitelist.txt` (белые
списки) — такие конфиги попадают в подписку **всегда**, независимо от
результата теста, и не расходуют лимит `--max-output`.

## Источники конфигов

Уже вписаны проверенные (на 12.08.2026) источники:

- **igareck/vpn-configs-for-russia** — под обход РКН, автотест каждые
  ~2 часа. `BLACK_VLESS_RUS_mobile.txt` → `sources.txt`,
  `Vless-Reality-White-Lists-Rus-Mobile.txt` → `sources_whitelist.txt`.
- **Au1rxx/free-vpn-subscriptions** — обновление раз в час, HTTP-проверка
  перед публикацией, есть версии по странам (Германия и т.д.).

Можно добавлять любые другие raw-ссылки — твой скрипт всё равно
перепроверит их заново по своим более строгим критериям.

### Telegram-каналы как источник

Добавь в `sources.txt` / `sources_whitelist.txt` просто `@имя_канала`
или `https://t.me/имя_канала` — скрипт откроет публичное веб-превью
канала (без бота, без логина) и вытащит `vless://` / `vmess://` /
`trojan://` / `ss://` ссылки из текста последних постов.

**Ограничение**: работает только для конфигов, вставленных текстом. Файлы
(документы), приложенные к посту, так не читаются — Telegram не отдаёт
их содержимое в HTML-превью. Варианты:
1. Проверь, не дублирует ли автор конфиги текстом в подписи к файлу.
2. Если файл — просто зеркало GitHub/Gist-ссылки, добавь эту ссылку
   напрямую в `sources.txt`.
3. Скопируй содержимое файла вручную в `manual.txt`.
4. Автоматизация чтения файлов из Telegram возможна через Bot API/MTProto
   (Telethon), но требует твоего `api_id`/`api_hash` — их нельзя класть в
   публичный репозиторий текстом, только через GitHub Actions Secrets.
   Скажи, если понадобится — соберу отдельно под конкретный канал.

## Все настройки (правишь в `.github/workflows/update.yml`)

```
--max-output 20          сколько лучших конфигов в каждой подписке
--max-latency-ms 350     потолок пинга (мс)
--min-speed-kbps 250     минимальная скорость закачки (КБ/с)
--round-gap 30           пауза между раундом 1 и 2 (сек)
--timeout 6              таймаут пинг-проверки (сек)
--speed-timeout 8        таймаут проверки скорости (сек)
--workers 20             параллельных тестов одновременно
```

Если после запуска подписка оказалась пустой (или почти) — источников
маловато для таких строгих порогов. Либо смягчи `--max-latency-ms` /
`--min-speed-kbps`, либо добавь источников.

Расписание — `cron: '0 */6 * * *'` в workflow (каждые 6 часов). Можно
поставить `'0 */3 * * *'` — каждые 3 часа.

## Запуск локально (для отладки)

```bash
pip install -r requirements.txt
# скачай xray-core: https://github.com/XTLS/Xray-core/releases
python scripts/build_subscription.py --xray-bin ./xray
```
